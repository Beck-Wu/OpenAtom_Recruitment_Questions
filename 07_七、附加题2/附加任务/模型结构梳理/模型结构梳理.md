# MiniMind 与 LLaMA 核心概念对应表
| LLaMA 概念 (论文) | MiniMind 代码位置 (model/model_minimind.py) | 在 MiniMind 中的作用 |
|:--|:--|:--|
| Token Embedding & lm_head	| self.embed = nn.Embedding(...) 与 self.lm_head = nn.Linear(...) | 将输入的 Token ID 映射为向量，最后将隐藏层向量映射回词表概率。MiniMind 通常共享 Embedding 与 lm_head 的权重以节省参数。 |
| Causal Self-Attention | Attention 类中的 forward 方法 | 核心自注意力机制。MiniMind 通过 attention_mask（下三角矩阵）实现因果遮罩，确保每个位置只能看到自己和之前的 token，不能“偷看”未来。 |
| RMSNorm | RMSNorm 类 (约 49-59 行) | 前置归一化。在 Attention 和 FFN 之前对输入进行归一化。相比 LayerNorm 去掉了均值中心化，计算更快，是 LLaMA 稳定深层训练的关键。 |
| RoPE | apply_rotary_pos_emb 函数 | 旋转位置编码。不直接加在 Embedding 上，而是在每一层的 Q 和 K 向量上应用旋转。MiniMind 支持 YaRN 外推，可在推理时将上下文从训练长度扩展到 32768 token。 |
| GQA | Attention 类中的 num_key_value_heads (默认 4) 与 num_attention_heads (默认 8) | 分组查询注意力。Key/Value 头数少于 Query 头数，大幅减少推理时的 KV Cache 显存占用，同时保持接近多头注意力的性能。 |
| SwiGLU 前馈网络 | FeedForward 类 (约 219-232 行) | 门控线性单元。使用 gate_proj、up_proj、down_proj 三个线性层，配合 SiLU 激活。相比 ReLU，SwiGLU 在同等参数量下性能更好，是 LLaMA 的标准配置。 |
| KV Cache | Attention.forward 中的 past_key_value 与 use_cache 参数 | 推理加速。自回归生成时，缓存之前所有 token 的 K 和 V，避免重复计算。生成第 N 个 token 时只需计算当前 token 的 KV 并拼接。 |
| 下一个 Token 预测 | MiniMindForCausalLM 类中的 forward，计算 loss | 模型输出 Logits 后，通过 交叉熵损失（F.cross_entropy）计算与真实下一个 token 的差距。这是预训练（Pretrain）和 SFT 阶段的核心训练。 |
